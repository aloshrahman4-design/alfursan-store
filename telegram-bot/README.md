# بوت تيليجرام لمعالجة صور المنتجات وأتمتة التسعير

بوت يستقبل صورة منتج واحدة أو ألبوم كامل (حتى 10 صور دفعة واحدة) من
المورد، يستخرج بيانات كل منتج (كود الموديل، التعبئة، القياسات، سعر
المفرد و/أو سعر الدرزن)، يطبّق هامش ربح محدد رياضياً، يعدّل أرقام
الأسعار فقط داخل الصورة مكانها الأصلي (دون المساس بالمنتج أو الشعار أو
QR)، ويعرض معاينة لكل الدفعة مع زر نشر جماعي مباشر إلى القناة.

## 1. التحدي الحقيقي: تصاميم الموردين غير موحّدة إطلاقاً

بعد مراجعة نماذج حقيقية من عدة موردين تبيّن أن لا يوجد "قالب" واحد يمكن
الاعتماد عليه:

- **شكل البطاقة يختلف كلياً بين مورد وآخر**: شريط أبيض أسفل الصورة،
  شريط ملوّن (أخضر/ليموني)، نص مكتوب مباشرة فوق الصورة بدون أي خلفية
  منفصلة، أو بطاقة في الزاوية العلوية.
- **تسمية الأسعار تختلف**: "درزن/دينار" و"قطعة/دينار"، أو "D/DOZ" و
  "D/PC"، أو كلمة "سعر" وحدها بجانب رقم مع "مفرد" لرقم آخر، أو ببساطة
  رقمان بدون أي تسمية نصية إطلاقاً (الأكبر دائماً هو سعر الدرزن، لأنه
  ≈ ×12 من سعر القطعة).
- **قيمة "التعبئة" تُكتب بصيغتين مختلفتين**: عدد صحيح = عدد القطع مباشرة
  (24، 18، أو حتى "18PRS")، أو عدد عشري = عدد الدرزنات (1.5 = 18 قطعة،
  1.25 = 15 قطعة).

بناءً على هذا، تم تصميم خطّي الاستخراج والتعديل ليكونا **متكيّفين مع أي
تصميم** بدل افتراض قالب واحد ثابت (كما كان مخططاً في المسودة الأولى).

## 2. البنية والحلول التقنية

```
telegram-bot/
├── main.py                # نقطة الدخول: معالجات تيليجرام + الدفعات (batching)
├── gemini_extractor.py     # الخطوة 1: استخراج + تحديد مواقع الأسعار عبر Gemini Vision
├── pricing.py               # الخطوة 2: حسابات الأسعار الحتمية (Decimal)
├── image_processor.py       # الخطوة 3: تعديل رقمي الأسعار فقط، مكانهما الأصلي (Pillow)
├── config.py                 # قراءة متغيرات البيئة والتحقق منها
├── requirements.txt
├── .env.example
├── fonts/                    # ضع هنا خطوط عربية .ttf (راجع fonts/README.md)
└── systemd/alfursan-bot.service
```

### أ. الاستخراج (`gemini_extractor.py`) -- تحديد موقع الأرقام وليس فقط قراءتها

بدل الاعتماد على تسمية نصية واضحة دائماً، البرومبت يُعلّم Gemini قواعد
تمييز صريحة (بترتيب أولوية): تسمية عربية صريحة (درزن/دزن/دستة، مفرد/قطعة)
→ تسمية إنجليزية (D/DOZ, D/PC) → "سعر" مقابل "مفرد" → رقمان بلا تسمية
(الأكبر = درزن) → سعر واحد فقط (يُعتبر سعر الدرزن). كما يُطلب من Gemini
أيضاً صندوق إحاطة (bounding box، مقياس 0-1000) حول **أرقام كل سعر فقط**
(بدون رمز العملة أو القوسين) -- هذا الموقع يُستخدم لاحقاً لتحديد أين
بالضبط يُكتب الرقم الجديد، بغض النظر عن تصميم البطاقة. لا حساب هنا
إطلاقاً؛ Gemini ينسخ فقط.

### ب. الحساب (`pricing.py`) -- بلا تغيير عن التصميم الأصلي

نفس المبدأ: مصدر واحد للحقيقة هو **مجموع الكارتونة**، والزيادة تُطبَّق
عليه مباشرة، ثم يُشتق سعر المفرد والدرزن من رقم واحد نهائي (بعد التقريب)
لضمان توافق `سعر المفرد × 12 = سعر الدرزن` دائماً بلا أي انحراف. تمت
إضافة `parse_pack_quantity()` لتفسير "التعبئة" تلقائياً (عدد صحيح = عدد
قطع، عدد عشري = عدد درزنات ×12)، و`_supplier_carton_total()` يستخدم سعر
الدرزن إن وُجد، أو سعر المفرد × عدد القطع كبديل إن لم يُذكر سوى سعر واحد.

### ج. التعديل (`image_processor.py`) -- تعديل جراحي بدل قالب ثابت

بدل رسم شريط أبيض موحّد فوق الصورة (لا يناسب كل التصاميم)، لكل سعر له
صندوق إحاطة من Gemini:

1. تُؤخذ عيّنة من **اللون الفعلي** المحيط بالصندوق (Pillow يقرأ البكسلات
   مباشرة) بدل افتراض خلفية بيضاء -- يعمل مع الشريط الأبيض، الشريط
   الملوّن، أو حتى النص المكتوب مباشرة فوق الصورة.
2. يُغطّى الصندوق بهذا اللون المُستخرَج (مع هامش أمان ~18% لامتصاص أي
   خطأ بسيط في تحديد الموقع).
3. يُكتب الرقم الجديد بلون نص يُختار تلقائياً (أسود أو أبيض) حسب سطوع
   الخلفية المُستخرَجة لضمان تباين واضح دائماً، وبحجم خط يتكيّف مع أبعاد
   الصندوق.

كود الموديل والقياسات والشعار وQR **لا تُلمَس إطلاقاً** -- فقط رقما
السعر يتغيّران، مما يحافظ على تصميم المورد الأصلي قدر الإمكان ويبدو
احترافياً أياً كان الشكل المصدر. إن تعذّر على Gemini تحديد موقع أحد
السعرين بثقة، يبقى الرقم القديم كما هو في الصورة (مع تنبيه ⚠️ في نص
المنشور يطلب مراجعة يدوية) بدل تخمين موقع خاطئ.

### د. المعالجة الدفعية (`main.py`) -- ألبومات حتى 10 صور

تيليجرام يُرسل كل صورة من الألبوم (media group) كرسالة منفصلة، والكابشن
عادة يظهر على صورة واحدة فقط من الألبوم. لذلك:

- تُجمَّع الصور الواردة بنفس `media_group_id` في ذاكرة مؤقتة، مع انتظار
  قصير (~2 ثانية سكون) قبل معالجتها كدفعة واحدة بنفس قيمة الزيادة
  المكتوبة في كابشن أي صورة منها.
- صورة واحدة مُرسَلة بمفردها تُعامَل كدفعة من عنصر واحد (بلا انتظار
  فعلي).
- كل صور الدفعة تُعالَج **بالتوازي** (حتى 3 صور في نفس الوقت) عبر
  Gemini، مع الاستمرار في باقي الدفعة حتى لو فشلت صورة واحدة (تُذكر في
  ملخص منفصل بدل إيقاف الدفعة كاملة).
- تُرسَل كل الصور الناجحة كألبوم معاينة واحد، مع رسالة ملخص وزرّي
  **✅ نشر الكل للقناة** / **❌ إلغاء** يطبّقان على الدفعة كاملة.

## 3. طريقة الاستخدام وآلية الحساب

1. أرسل للبوت صورة واحدة أو ألبوماً كاملاً مع كتابة قيمة الزيادة في
   كابشن أي صورة من الدفعة:
   - مبلغ ثابت: `+10000`
   - نسبة مئوية: `15%` أو `+15%`
2. لكل منتج في الدفعة، يحسب البوت السعر كالتالي (مصدر واحد للحقيقة =
   مجموع الكارتونة، حتى لا تتضارب الأرقام الثلاثة مع بعضها):
   1. `عدد القطع الكلي` يُشتق من قيمة "التعبئة" (رقم صحيح = عدد قطع
      مباشرة، رقم عشري = عدد درزنات × 12؛ مثال: `1.5` → 18 قطعة).
   2. `مجموع الكارتونة عند المورد = سعر الدرزن × عدد الدرزنات` (أو
      `سعر المفرد × عدد القطع` إن لم يُذكر سوى سعر واحد).
   3. تُضاف الزيادة على هذا المجموع مباشرة (مبلغ ثابت أو نسبة مئوية).
   4. `سعر المفرد الجديد = المجموع الجديد ÷ عدد القطع`، ثم
      `سعر الدرزن الجديد = سعر المفرد الجديد × 12` و
      `مجموع الكارتونة المعروض = سعر المفرد الجديد × عدد القطع`
      (تُشتق دائماً من سعر المفرد النهائي بعد التقريب، فلا يحدث فرق بسيط
      بين الأرقام بسبب تقريب مستقل لكل رقم).
3. يرد البوت بمعاينة: ألبوم الصور المعدَّلة (أرقام الأسعار فقط تغيّرت،
   في نفس مكانها الأصلي) + كليشة نصية لكل منتج، مع رسالة ملخص وزرَّي
   **✅ نشر الكل للقناة** و **❌ إلغاء**.
4. الضغط على "نشر الكل للقناة" يرسل نفس الصور والنصوص إلى `CHANNEL_ID`
   مباشرة (كألبوم إن كانت أكثر من صورة).

## 4. التثبيت المحلي

```bash
cd telegram-bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # ثم عبّئ القيم (التوكن، مفتاح Gemini، القناة، المستخدمون المصرح لهم)
```

نزّل خط عربي (مثل Cairo من Google Fonts) وضع ملفات `Cairo-Regular.ttf` و
`Cairo-Bold.ttf` داخل مجلد `fonts/` (راجع `fonts/README.md`) -- يُستخدم
فقط لكتابة الأرقام الجديدة، وهو نفس الخط الغامق (Bold) لأن الأرقام
الإنجليزية لا تحتاج تشكيلاً عربياً.

تشغيل تجريبي:

```bash
python main.py
```

## 5. النشر على سيرفر Ubuntu (systemd، يعمل 24/7)

```bash
# 1) إنشاء مستخدم مخصص وتحضير المجلد
sudo useradd --system --create-home --shell /usr/sbin/nologin alfursan
sudo mkdir -p /opt/alfursan-bot
sudo chown alfursan:alfursan /opt/alfursan-bot

# 2) نسخ الملفات إلى السيرفر (من جهازك المحلي)
rsync -av --exclude venv telegram-bot/ user@server:/opt/alfursan-bot/

# 3) على السيرفر: تجهيز البيئة الافتراضية
sudo -u alfursan python3 -m venv /opt/alfursan-bot/venv
sudo -u alfursan /opt/alfursan-bot/venv/bin/pip install -r /opt/alfursan-bot/requirements.txt

# 4) إعداد ملف البيئة
sudo -u alfursan cp /opt/alfursan-bot/.env.example /opt/alfursan-bot/.env
sudo -u alfursan nano /opt/alfursan-bot/.env   # عبّئ القيم الحقيقية

# 5) تثبيت خدمة systemd
sudo cp /opt/alfursan-bot/systemd/alfursan-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now alfursan-bot

# متابعة السجلات
sudo journalctl -u alfursan-bot -f
```

أوامر مفيدة لاحقاً:

```bash
sudo systemctl restart alfursan-bot   # بعد تحديث الكود أو .env
sudo systemctl status alfursan-bot
```

## 6. أمان وصلاحيات

- `ALLOWED_USER_IDS` **يجب** ضبطه في الإنتاج بمعرّفات تيليجرام لأصحاب
  الصلاحية فقط (يمكن معرفة معرّفك عبر بوت مثل `@userinfobot`)، وإلا
  سيستطيع أي شخص إرسال صور والنشر في قناتك.
- تأكد أن البوت مُضاف كمشرف (Admin) في القناة الهدف مع صلاحية "نشر
  الرسائل".
- لا تضع `.env` أو `GEMINI_API_KEY`/`TELEGRAM_BOT_TOKEN` في git — الملف
  موجود كمثال فقط (`.env.example`).

## 7. حدود معروفة

- تحديد موقع السعر (bounding box) يعتمد على قدرة Gemini على التموضع
  المكاني، وهي جيدة لكن ليست معصومة من الخطأ 100% -- لذلك يبقى الرقم
  القديم بدون تعديل مع تنبيه ⚠️ إن لم يكن البوت واثقاً من الموقع، بدل
  الكتابة في مكان خاطئ. راجع أي منشور يحمل هذا التنبيه يدوياً قبل النشر.
- تغطية اللون الجديد مستطيل مصمت بلون مُتوسَّط من محيط الرقم -- يعمل
  بشكل ممتاز مع الأشرطة/البطاقات ذات اللون المصمت (الغالبية)، وبشكل جيد
  عادة مع الخلفيات الفوتوغرافية غير المصمتة، لكنه ليس "إزالة كائن" ذكية
  (inpainting)؛ إن كانت خلفية السعر معقدة جداً (تدرّج لوني حاد أو نقشة)
  فقد يظهر المستطيل بشكل بسيط. للمنتجات ذات الخلفيات الفوتوغرافية
  المعقدة، راجع المعاينة قبل الضغط على نشر.
